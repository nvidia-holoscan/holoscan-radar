The dense path no longer needs the app-local `CubeAoaLookupOp` adapter (apps can migrate at leisure). Implemented + tested | 2026-07-21 |
| L2 — CFAR NCI `K > 1` α closed form | Adopt the **regularized incomplete-beta** relation as the pinned CA-CFAR calibration: `pfa = I_{1/(1 + α/N)}(N·K, K)`, inverted numerically for α per training-cell count `N` (host LUT), reducing to the locked `α = N·(pfa^(−1/N) − 1)` at `K = 1`. Ratifies the code-ahead-of-contract implementation (`cfar_alpha.cpp`); `OPERATOR_API.md` `pfa` / `nci_axes` bullets now state the relation. Validated by Monte Carlo (`CaMonteCarloPfaK1`, `CaMonteCarloPfaNciK8`). GO/SO/OS `K > 1` still calibrate by Monte Carlo (separate item, TEAM_BLOCKED L5). **Rejected:** reverting to the power-law placeholder `α = N·(pfa^(−1/(N·K)) − 1)` (misses target Pfa for `K > 1`) | 2026-07-21 |
| L3 — CFAR `max_cached_kernels` | **Drop from the contract** (chosen over keeping it as a forward-looking placeholder). The CFAR math is a single fused stencil that reads window extents as kernel args — nothing to compile or cache per footprint, so the parameter was inert. Removed from `OPERATOR_API.md` and from the operator (`cfar_detector_op.{hpp,cu}`); it was declared but never read and untested, so removal is behavior-preserving. A hollow knob implying eviction behavior is worse than its absence; re-introduce as a real wired parameter if a future variant needs per-footprint kernel caching. `guard_cells` / `training_cells` wording narrowed to note a footprint change needs no kernel rebuild (may recalibrate the α LUT) | 2026-07-21 |
| L4 — CFAR OS `os_rank` indexing | Ratify **0-based, ascending**: training-cell powers sorted low→high, noise estimate at index `os_rank` (rank 0 = smallest), typical `≈ floor(0.75·N)`; border cells clamp to `train_cnt − 1`. Matches array indexing + the existing MC-validated implementation, so docs-only — `OPERATOR_API.md` `os_rank` bullet now states it. Pinned by `test_cfar_detector_os.cpp`. **Rejected:** 1-based / descending (would need a code + test + LUT change with no upside absent an external spec) | 2026-07-21 |
| L5 — CFAR `alpha_lut` / calibration contract | **Adopted as locked text** (PROPOSED banner dropped in `OPERATOR_API.md`). Locks: `alpha_lut` [live] fast-path LUT (CA/OS by training count `n`, GO/SO by `go_lut_index`; `pfa` ignored when set); `blocking_alpha_lut_rebuild` (serve-stale vs block); `nci_fold` hint (apps derive it from `array_geometry.num_elements()`); **start-time pre-calibration for CA/OS** (map-size-independent) with **GO/SO excluded** (aliased `go_lut_index` is map-dependent, non-convergent at low `pfa`); **warn-once on any runtime calibration**; narrowed `pfa` wording (closed-form CA/OS-K1, MC GO/SO/OS-K>1). **Deferred:** scalar `alpha`, hybrid modes, offline LUT-gen, GO/SO start-time pre-warm. Verified in-container (CFAR suites + apps pre-calibrate) | 2026-07-21 |
| L1 — CFAR/mask bool dtype vs HSDK 4.3 DLPack | **Change mask dtype to `uint8` (0/1)** for `CFARDetectorOp.detection_mask` and `SnapshotGatherOp.is_valid` (chosen over keeping `bool` + betting on the unvalidatable HSDK 5 fix, and over a parallel compat port). HSDK 4.3's DLPack path has no NumPy typestr for `kDLBool`, so a bool port throws in Python; 4.3 is the supported floor. `uint8` is byte-identical to the 0/1 bytes the kernels already write, so only the emitted `DLDataType` changed (kernels/compaction untouched). Consumers (`is_valid_mask`, MVDR) still **accept** `bool` or `uint8`. `OPERATOR_API.md` updated; Python tests capture the masks directly. Verified in-container | 2026-07-22 |
| L11 — `AngleConvention::kCustom` boundary mapping | **Implement** the generic `custom` mapping (chosen over deferring). Builds an orthonormal frame from the signed-axis fields and maps `(az, el)` to a canonical direction (+ `zenith` polar step), inverted by projection; the three axes must be distinct principal axes (a degenerate config throws at steering-table build). Every named preset is a specific `custom` config, which anchors correctness: `test_angle_convention.cpp` asserts `custom` reproduces each preset, round-trips, and rejects degenerate axes. Implemented in `angle_convention.cpp` (shared by Beamscan + PhaseShift); Python bindings already expose the axis fields; `OPERATOR_API.md` `custom` bullet updated. Verified in-container, no regression | 2026-07-22 |
| L15 — CFAR non-blocking alpha-LUT rebuild SEGFAULT | **Root-caused + fixed** (chosen over gating the non-blocking path behind an opt-in). Confirmed a thread/CUDA-context **lifetime** bug, not a table-tearing race: `ensure_alpha_lut_build` detaches a thread that (for GO/SO/OS) runs GPU Monte Carlo; nothing joined it, so a build launching kernels after Holoscan tore down the CUDA context faulted in `cuLaunchKernel` (reproduced 5/20; cuda-gdb stack pins it). The reader copies the LUT under the cache mutex, so double-buffer was a red herring. Fix: `detail::join_inflight_alpha_lut_builds()` drained by a new `CFARDetectorOp::stop()`. De-flaked the test (tick-1 latency, not total `run()`); 40/40, 0 crashes | 2026-07-22 |
| L14 — S3 subarray-selection forks | **Ratify all four** (`SubarraySelectionOp` already implemented + tested; docs-only). (1) **Auto default** (largest filled ULA/URA sub-block) + **explicit** channel-index escape hatch. (2) Objective = **max element count** (DOF), ties broken by larger **azimuth aperture** — over max-aperture-first. (3) **Contiguous only**; sum-set "Harnessing Holes" (non-contiguous, holes kept for aperture) **deferred** to the Roadmap. (4) **Standalone op** (not a mode inside `VirtualArrayAssemblyOp`) — both landed independently, clean separation. No consumer for any alternative; the op + `radar_common/dsp/subarray_selection` helper + tests already reflect it | 2026-07-22 |
| L13 — S1 spatial-smoothing forks | **Ratify both forks** (already implemented + tested; docs-only). (a) The `spatial_smoothing` integer is a per-aperture-axis sub-array **count** `P` (`L_axis = M_axis − P_axis + 1` derived), matching the "number of looks to average" convention — chosen over sub-array length. (b) A non-uniform / holey array is **rejected with a clear error → reduced upstream via `SubarraySelectionOp` (S3)**, not accepted as in-operator explicit partitions (which would duplicate S3) — clean separation: S3 owns holey→uniform, the smoother owns filled ULA/URA. No consumer for either alternative. `OPERATOR_API.md` `spatial_smoothing`, the `radar_common/dsp/spatial_smoothing` helper, and `test_spatial_smoothing` already reflect it | 2026-07-22 |
| L12 — Non-uniform / staggered TDM schedules | **Ratify uniform round-robin as the v1 scope** (chosen over building staggered-TDM support). Non-uniform / staggered schedules (varying TX dwell or count) stay rejected with a clear error: no consumer (FMCW workflows are uniform TDM), and support would span a new per-TX-timing descriptor + `MIMODeinterleaveOp` + a generalized `MIMOCoherentCompensationOp` compensation model (itself an unresolved design question) + simulator + tests. Already enforced (contract, `TXSchedule::expand_chirp_tx_index`, `RejectsNonUniformSchedule` test); docs-only — scope now stated in the operator headers, fmcw README, and `OPERATOR_API.md`. **Deferred:** staggered TDM tracked on the Roadmap below (MIMODeinterleave OPEN_ITEMS B.1) | 2026-07-22 |
| L9 — ClusterDBSCAN border-point tie-break | **Ratify min-root** — an inter-cluster border point (reachable from cores in >1 cluster) joins the core neighbor with the numerically smallest component root; pinned in `OPERATOR_API.md` `labels`. Chosen over nearest-core (adds kernel distance-tracking + a secondary tie-break for no partition-level benefit) and over scikit-learn's first-reached rule (**rejected** — order-dependent, breaks the order-independent `labels`-is-a-pure-function guarantee). Only affects the rare straddling border points; the partition and downstream `DetectionReductionOp` are unaffected. Docs-only (already implemented + tested) | 2026-07-22 |
| L8 — ClusterDBSCAN `epsilon` scalar-vs-vector encoding | **Ratify the length-1-vector encoding** (`epsilon: [0.5]` for the isotropic/scalar case; length `num_features` for per-axis). Chosen over adding a bare-scalar (`epsilon: 0.5`) YAML/Arg converter: the `[list]` idiom is already uniform across every vector parameter (`guard_cells`, `training_cells`, `nci_axes`, `spatial_smoothing`), so ratifying it is the consistent choice, whereas a scalar special case for `epsilon` alone is inconsistent and invites the same converter everywhere (scope creep for a cosmetic gain). Docs-only — `OPERATOR_API.md` `epsilon` bullet tightened to state the one-element-list convention | 2026-07-22 |
| L7 — ClusterDBSCAN `max_clusters` surplus policy | **Keep the largest clusters** — realized by numbering ids by descending size (L10), so the existing "drop highest ids" cap drops the **smallest** surplus clusters (their points → noise `-1`, keeping `labels`/`sizes` consistent). Chosen over the prior spatially-arbitrary ascending-root drop, and over "leave surplus `labels` populated / truncate only `sizes`" (**rejected** — breaks the `sizes[label]` invariant). `OPERATOR_API.md` `max_clusters`/`sizes` updated; landed + tested (`MaxClustersKeepsLargest`, C++ + Python). Parameterizing the order is deferred (ClusterDBSCAN OPEN_ITEMS §8) | 2026-07-22 |
| L10 — ClusterDBSCAN cluster-id numbering order | Pin **descending point count** (cluster 0 = largest), ties broken by **ascending component root** (lowest member row index); `sizes` non-increasing. Chosen over the prior ascending-root numbering — descending size gives a "cluster 0 is largest" guarantee and makes the `max_clusters` cap keep the largest (L7) for free. Deterministic (`labels` a pure function of `(points, epsilon, min_points)`). Implemented via a host argsort of per-id counts + a `remap_labels` GPU pass; `OPERATOR_API.md` `labels`/`sizes` updated; tested (`NumbersClustersByDescendingSize`). **Deferred:** a `cluster_order` param for alternate orders (OPEN_ITEMS §8) | 2026-07-22 |
| L6 — CFAR exact-sized `detection_idx` | **Ratify exact sizing** (chosen over a capacity + `num_detections` port). Accept the per-tick scalar device→host count sync as the cost of the contract: it moves one integer, and the exact-size, no-companion shape is load-bearing across the downstream chain (`SnapshotGather`/`FeatureAssembly`/`DetectionReduction`/`ClusterDBSCAN` all positionally join on "row count *is* `num_detections`"), so breaking it is a broad change unjustified without a measured latency budget the sync violates. Docs-only — the locked `detection_idx` contract is unchanged. **Deferred:** a capacity + `num_detections` port as an **opt-in** fast path, added only if profiling shows the sync bounds latency (CFAR OPEN_ITEMS §8) | 2026-07-21 |

## Roadmap (deferred capabilities)

Capabilities deliberately **out of the current scope** — settled as deferred (no
current consumer / larger project), not blocked. Each is enforced today with a
clear error or documented limitation; pick one up when a concrete consumer
needs it.

| Capability | Why deferred | Where tracked |
| --- | --- | --- |
| **Staggered / non-uniform TDM schedules** (varying TX dwell or count) | Needs a per-TX-timing schedule descriptor **and** a generalized `MIMOCoherentCompensationOp` model (the compensation for arbitrary timing is an open design question). Uniform round-robin covers the FMCW workflows; non-uniform is rejected with a clear error today. Settled L12 | [MIMODeinterleave OPEN_ITEMS B.1](../../operators/fmcw/mimo_deinterleave_op/OPEN_ITEMS.md) |
| **Sum-set ("Harnessing Holes") holey subarray smoothing** | S3 selects a contiguous filled ULA/URA today; a sum-set decomposition (`S_b + S_c`, keeping holes for aperture when the array is sum-set smoothable) would recover more DOF / aperture from holey MIMO co-arrays. Research item — no consumer, and the gridless estimators (Root-MUSIC/ESPRIT) aren't built yet. Settled L14 (fork 3) | [SubarraySelection OPEN_ITEMS](../../operators/angle_estimation/subarray_selection_op/OPEN_ITEMS.md) |
